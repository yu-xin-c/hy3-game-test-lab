# 原始方案的跨游戏断言核验

保留 v1，新增原始 Hy3 Target Rush、Platform Rescue 两份方案的前两步，按原始编号形成长度 1、2 的前缀。全部纳入，不按结果筛选。它们是事后诊断样本，不是随机留出集；同一游戏的前缀相关，不能按独立游戏计数。

Target：步骤 1 检查真实 Start 后 playing 和 game_started；步骤 2 在同一上下文以 seed=42 重置、开始并点击五个目标，重复一次，比较每次点击前的 DOM 边界框。Platform：步骤 1 比较 seed=42 重置后同一真实输入和虚拟时间表下 player.x/y/vx/vy、latest_event_seq；步骤 2 检查按住右键、tick 0/20/40 跳跃是否产生指定三次着陆，随后 key_collected、game_won。三个全新 Chromium 上下文，每个两次重置。游戏文件哈希必须与原生成记录一致，不能写玩家状态。

平台使用 Start 后 0/320/640ms 的键盘输入，保留输入前 tick。运行中的输入 tick 偏差记证据不足；若此前输入均符合要求，但在下一次计划跳跃前已出现 game_lost 并停止 tick，这是直接反证。最多观察 3200ms，没有终局不能独自否定无限等待。已经 lost 或 key_collected 在指定着陆完成之前发生，才有直接反证。步骤 2 的“无穿模”未完整采样，不将整条断言判为通过；无直接反证则未知。

修订记录：初次浏览器观测保存在 results/plan-claims-v2-browser，初版规则把终局停钟也判为时序偏差，步骤 2 为未知。发现六次均在下一次计划跳跃前输局后，补充上述终局规则及单元测试，再以新目录 results/plan-claims-v2-final 重新执行。两版都保留；规则修订在任何本实验的模型评审之前进行，不能称为事先未见样本的盲测。

先执行浏览器并冻结观测、判据结果和模型输入，再调用 Hy3。模型只看原文步骤、观察数据与范围说明，不看标准标签。计分单位为前缀，重复不增加分母。错误前缀须同时检出错误并准确定位；正常前缀统计误报；未知单列。此处评估选定 verification 断言，不认证 implementation、完整计划或整个游戏。定位是最早被证据反驳的所选方案步骤，不是原始生成过程的因果首错。

比较对象是原文一步/两步前缀；没有模型优劣或模块收益主张，不做模型基线和消融。与 v1 并列报告，不合并成随机泛化率。效率保留调用凭据 usage，不主张速度优势。真实浏览器三次重复用于检查复现稳定性。解释只要求对应原文和观察，不评价内部思维。
