# Target Rush 原方案后四步核验

对象为原始 Hy3 Target Rush 方案的步骤 3–6。步骤 1、2 的原文、浏览器证据与独立标准复用 plan-claims-v3，不改写也不重新计数。新增浏览器操作按原 verification 的可执行部分安排：步骤 3 命中、空白失误、HUD 点击；步骤 4 五次命中、三次失误、计时归零及终局后事件；步骤 5 Restart 按钮与 KeyR；步骤 6 观察接口、事件过滤、HUD 文字。

每项在三个新 Chromium 上下文执行，种子 42，800×600，暂停虚拟时钟，全部玩家操作用真实鼠标或键盘。调用只读观察接口，不直接写游戏状态。先核验原生成代码来源，再冻结观测、标准和模型输入哈希，随后请求 Hy3。未执行的实现细节及全种子性质单列证据不足，不将选定断言通过推广为整份方案正确。

模型判最早被执行证据反驳的原步骤，未知另计。前缀长度 3–6 与长度 1、2 来自同一原方案，彼此相关；重复实验不扩大分母。对照为原先只看两步的范围与新增四步的范围，没有其他模型基线或模块增益主张。保留模型用量，不比较速度。浏览器三个上下文检查复现；解释只比对原方案原文和真实观测，不评价内部思维。

结果完成后，可做一个事后描述性汇总：每款原始游戏仅选已经保存的最长且凭据有效的方案前缀，三款游戏分别为 Target Rush 6 步、Platform Rescue 2 步、Signal Memory 2 步。按游戏而不是相关前缀计数；这只说明这些已测断言的首错判断，不能称为预先盲选的完整推理正确率或游戏最终答案准确率。
