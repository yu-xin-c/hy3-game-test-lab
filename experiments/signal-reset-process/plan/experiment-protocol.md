# Signal Memory 重开后旧计时器检查

对象是原始 Hy3 生成方案的第 5 步：Restart 按钮与 KeyR 应恢复菜单状态，公开实现方案明确要求 `phase='menu'`。只检查这一条公开主张，不重算整份方案的首错；原方案第 2 步已有独立反例。

固定源文件和原方案，浏览器隔离外网、视口 800×600、seed=1。每个新 Chromium 上下文分别执行无播放的重置对照，以及播放开始后立即或 800ms 时按 Restart/KeyR。立即观察一次，再用虚拟时间推进 1600ms 后观察。玩家操作用真实点击或键盘；桥只读状态和事件。三个独立上下文用于复现，不扩大方案样本数。

先用确定性断言判定即时菜单状态、延时菜单阶段及重置后的事件。两者分开计数，避免把即时通过误写为整个重开过程成立。冻结原方案、生成代码、观测和标准的哈希后，才给 Hy3 判断第 5 步是否被反驳、首错步骤和错误类别。标准来自原方案和真实运行，不由待评模型生成。

本实验只有一个原游戏和一条过程主张；无训练/测试拆分、速度或模块增益主张。即时检查是公平的旧基线，延时检查检验异步边界；无播放的重置是对照。不同重开方式与 800ms 时机检验稳定性。代码来源通过已记录的 Write/Edit 重建核验，运行反例与代码来源分别呈现，不以静态匹配代替运行证明。不画统计图。
