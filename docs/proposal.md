# GameTestLab 项目方案

更新：2026-09-15

## 要解决的问题

AI 生成的游戏能打开、能点击，仍可能存在玩法错误。例如跳不到平台、失败后界面仍显示进行中，或者重开没有清空状态。项目通过实际试玩发现异常，再检查相关实现和生成记录。

## 实现方式

Hy3 根据公开需求生成游戏。新增生成流程同时保存编号实现方案和真实代码修改，不采集模型内部思维链。私有检查不进入生成提示。

Playwright 在 Chromium 中发送真实输入。固定路径用于稳定回归，混元根据页面和只读对象状态选择的路径用于探索。计时玩法通过浏览器虚拟时钟推进，不直接修改作物、生命或胜负。

| 层级 | 检查内容 |
| --- | --- |
| L1 运行 | 加载、启动、输入及浏览器错误 |
| L2 逻辑 | 状态、事件、分数、胜负和已定义的物理条件 |
| L3 界面 | HUD、可见控件和截图证据 |

出现问题后，保存首个可观测异常及后续结果，再由混元复核公开需求、代码和执行记录。代码引用必须逐字匹配，工具日志必须能重建最终文件，才能标明来源。操作首错、代码写入步骤和公开方案错误分别记录。

Vitest/jsdom 验证比较器、数据契约及 DOM 逻辑。实际可玩性以 Chromium 证据为准。可选多模态模型只辅助界面检查，不测试摄像头、视频理解和语音交互类游戏。

## 题集与验证

96 道自建游戏任务参考用户提供的玩法分布构造，每题包含公开需求、难度依据、固定路径及私有检查。重复运行固定 seed，冻结输入和生成文件哈希。当前标准存在部分语义疑问，原始规则结果与模型复核分列。

评估器采用正常实现与错误实现的自动运行对照。标准先冻结，模型评审后再计算指定要求的定位准确率和误报率。三次重放验证稳定性，不扩大独立样本数。详见 [验证报告](../reports/validation-report.md)。

## 当前结果

- 96 题生成、876 次浏览器路径执行、292 个场景的混元复核已完成。
- 新增 3 题公开方案生成过程实验，保存真实工具修改和逐步复核。
- 3 款游戏完成混元自主探索，支持固定输入复验和只读页面展示。
- 真实游戏两条要求的四个实现对照完成自动验证，但尚未独立验证公开方案的首错定位率。

详细指标、反例和局限见 [分析报告](../reports/analysis-report.md)，不把运行层面的过程通过率写成生成推理正确率。

## 时间与交付

活动安排为 8/27 提交方案、9/11 提交作品终稿。仓库中的实际运行与更新日期单独记录，不将后续补充标作截止日前完成。

交付包含源码、分层任务与检查脚本、运行记录、自动验证数据、分析报告和六页 PPT。视频由用户负责，不在本次制作范围内。

## 风险

观察桥也可能实现错误，因此需要用页面和运行对照交叉检查。测试脚本失败不一定是游戏失败，模型复核也可能漏检或误引证据。难度分层受任务和检查差异影响，现有结果不足以确定稳定能力临界点。
