# 三阶段题：公开规则与状态判据对照

在 96 题中，78 题明确使用同一类三阶段规则。独立参考程序只接受题面同时明确写出的规则：三步顺序、每步 10 分、错误清空进度并扣生命、第二次错误失败，以及重开恢复初始值。其余 18 题不套用本模型。

按原固定路径计算 status、progress、score、lives：1,482 个检查点字段与原标准一致，没有确定性不匹配。另有 432 个字段属于模型范围之外，如 last_action、connected、saved、best_score，未据此认证。数量按“场景—检查点—字段”计算，不是去重检查项，不能从 5,182 个清单项中直接扣除。

该程序不读取生成的 game.js，不读取 Hy3 核对意见，也不从 oracle 取值构造参考状态。oracle 只在状态算完后用于比较。刷新仅按公开的恢复要求保留参考状态，不能证明实际游戏确实写入并恢复了存档；JOIN 不认证通信正确性。

规则未明确规定部分进度后犯错是否清空分数，参考程序保留该不确定性，不擅自补成 0。最后获胜时 score=30 则有明确公开依据。模型也不判断事件、HUD、触控和三维画面的实现。

这些题共享相同的核心状态机，因此 78 题不是 78 种独立玩法逻辑。本次批量一致性核验能检查模板生成判据的基础算术与状态值，不能据此声称覆盖了丰富游戏机制或完整标准集。

result.json 包含逐题输入哈希、全部参考轨迹、逐项对照和参考程序哈希。

pnpm exec tsx scripts/verify-stage-oracles.ts --out artifacts/stage-oracle-new
