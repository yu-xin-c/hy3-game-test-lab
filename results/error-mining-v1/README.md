# 从真实生成游戏中找错误

来源：已有 96 题去重结果。先筛选历史 Hy3 判定过程有问题的场景，再对其中三个候选使用真实 Chromium 复验。不是新造故障，不是 QiraBot 接入结果，也不是随机抽样的总体准确率。

每个游戏使用原始、哈希核验过的 Hy3 代码，独立浏览器上下文重放 3 次。真实鼠标或键盘输入，每步推进 100ms，最后再推进 1000ms，排除单帧渲染滞后的解释。禁止远程资源，不修改游戏状态。

| 游戏 | 复验问题 | 复现 |
| --- | --- | --- |
| Particle Orchestra | A/C/D/B 后获胜，但得分 200，题面要求 100 | 3/3 |
| Zen Garden | 两次错误后逻辑为 lost，等待后 HUD 仍未显示 Lost | 3/3 |
| Science Circuit | 进入游戏并完成一步后，Restart 按钮仍不可见 | 3/3 |

注意：复现的是现象，不自动等于确认需求违反。Particle Orchestra 的“获胜并得到100分”存在总分/额外奖励的解释分歧，混元两次复核给出不同判断；该例标为需求歧义候选，不能直接收入确定错误标准集。最小改动能说明分数来源，不能消除题面歧义。

逐次操作、状态和 HUD 在各游戏 JSON 中，截图以游戏名命名。生成历史均能重建至最终文件；代码来源不等于已证明最早推理错误。


更新：初次复核只发送单题题面，漏了公共接口规范。使用 `--full-prompt` 补发原始公开生成提示，另存 `*-full-review.json`，旧记录保留但不作为完整评测。详细进度见 [定位报告](REPORT.md)。

另有 12 次最小改动诊断对照，记录在 `causal-checks/result.json`。仅改变浏览器收到的脚本响应，原始文件不变；两类问题均随对应改动消失。这不是重新生成的游戏或修复后的正式成绩。

复验命令：`pnpm exec tsx scripts/mine-game-errors.ts`（输出目录必须不存在，避免覆盖原始证据）。混元审查：`pnpm exec tsx scripts/judge-mined-errors.ts --cli /absolute/path/to/codebuddy`。
