# 流星题：时间边界与测试路径

公开落点是 `1000/2000/3000/4000ms` 对应轨道 `1/0/2/1`。原冻结 win-path 在第一波处理前把玩家切回轨道1，实际遭流星击中，后续通关检查自然失败；原 loss-path 在浏览器观测的 `elapsed_ms=992` 就要求 1000ms 的击中已经发生。混元把这两处归为测试路径/检查点问题，而不是认定代码不能通关。

[追加 Chromium 对照](grounded-probe.json)不修改原答案和原记录。按题面落点避让，每波完成后才调整轨道，四波依次得到 `wave=1..4`、分数 `100..400`，终局 `status=won,score=500,best_score=500`；隔离重放通关 **3/3**。停留初始轨道到第一波的失败对照 **3/3**。这验证该玩法和时间处理的关键路径，但不替代其他界面、manifest 和完整过程方案检查。
