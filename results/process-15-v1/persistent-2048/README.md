# 2048：游戏能玩，原方案预测却错

原冻结浏览器评测在玩家动作前停止：游戏的 `observe()` 多返回了 `protocol`，严格观察对象解析器拒绝该额外字段；原记录的九次运行都没有实际完成试玩。混元原复核把它归为测试问题，同时也指出原方案第 3 步的错误预测；这两项不能混为同一错误。

[追加真实键盘与刷新对照](direct-probe.json)绕过的只是观察对象严格解析，不改游戏或私有答案。右滑后刷新恢复棋盘，再下滑合成 8 获胜 **3/3**；右滑后上滑同样合成 8 获胜 **3/3**，所以原编号方案写的“上滑不产生 8、应该输”明确不成立；右滑后左滑没有 8，按规则失败 **3/3**。获胜后额外键盘输入不增加步数，Restart 回菜单并清除存档。真实玩法结果正确，不等于额外 `protocol` 字段符合严格观察接口。

这是“核心玩法终局正确，但公开方案中的一个验证步骤错误”的自然案例。原混元复核把该步骤标为已修复，却给整份过程 `null`、首错 `null`；是否把最终交付计为完整正确，需要把游戏玩法和观察接口格式分别列出，不能用原动作前失败数替代。
