# 五子棋：把测试时机、玩法、方案首错分开

原固定路径在主页面点 Start 后立刻要求 `playing`；题目是先创建房间、再让副页面加入，当前不应提前开局。公共接口合同还要求点击 Start 就记录 `game_started`，代码却等两页就绪才记录：同一个检查点里有测试时机问题，也有事件时机问题，不能一概归为测试错误。短版混元复核成功恢复了超时调用，但原失效调用及模型的 `test_problem` 判断仍保留。最终 manifest 的 `winner.type` 数组联合类型又被严格合同拒绝，这是另一项交付缺陷。

[追加双页面真实输入](grounded-room-probe.json)确认加入流程 **6/6**、P1 连五子获胜 **3/3**、P2 连五子获胜 **3/3**。这些路径避免了原私有失败路径让 P2 只落四子就要求 P2 胜的问题；它们不消除交付格式缺陷。

[原方案步骤核验](ROOM-PLAN-CLAIMS.md)再找到两个过程主张错误：第 4 步说 reset 把 tick 清零，实际 **0/3**；第 5 步说 Restart 保持连接和 Playing，题面要求清房间，实际 **0/3**。前三步核心玩法的已执行前缀正常，第 4 步是目前最早的已知错误主张。混元判过程错误却给 `first_error_step=null`，这是定位漏检；不能拿模型自己的“过程错误”意见当成定位准确。
