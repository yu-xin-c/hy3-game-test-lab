# 双页面同步：标准错误与实现错误分开

公开题面要求 `connected` 出现在状态中，但没有规定它是“连接人数”。冻结私有检查要求它在加入后精确等于数字 `2`、重开后等于数字 `0`；实际代码用布尔值 `true/false`。混元判据来源核对把加入后的数字 `2`（A24）标成歧义，却把重开后的数字 `0`（A42）误判为有依据。两条数字检查不能单独证明游戏错误，原浏览器结果仍保留。

另一问题是最终交付的 `game.manifest.json` 把 `winner.type` 写成 `["string","null"]`，而公开合同只接受一个 JSON 类型。当前严格合同检查确实拒绝该文件；原编号方案第 6 步就提出了“string 或 null”的联合类型，能把这个错误追到具体方案和生成代码。混元还提出接收方没有记录 `player_moved` 事件，与方案第 2 步的“每次前进发射事件”主张不一致；代码与页面事件记录支持这个现象，但公开需求未明说每个接收页面都要重复记录该事件，所以不能仅用它锁定全链首错第 2 步。

双页面真实输入已观察到 P2 位置同步到主页面并判 `winner=secondary,status=lost`。这不消除 manifest 缺陷，也不意味着原三个路径失败都由游戏造成。
