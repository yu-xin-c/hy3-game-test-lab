# 赛车题：先修测试路径，再判游戏

公开规则的障碍是 `(1000ms,车道1)`、`(2000ms,车道0)`、`(3000ms,车道1)`、`(4000ms,车道2)`。原冻结 win-path 在第一个 1000ms 边界刚到就把车从车道0切回车道1；下一帧处理障碍时实际撞车，原浏览器记录从动作 4 开始判输。loss-path 则在实际 `elapsed_ms=992` 时提前要求已经碰撞。混元复核把两处标为 `test_problem`，未声称原路径已经验证胜利分支。

[追加浏览器对照](grounded-probe.json)不修改原题面、原私有答案或原执行记录。它在第一个障碍处理后才切回中间车道，接着依次避开车道0、1、2。隔离 Chromium 重放三次，**通关 3/3、应输 3/3**：每个中间点依次有 `passed=1,2,3,4`、分数 `100,200,300,400`，终点 `status=won`、`score=500`、`collisions=0`。这确认原固定路径错误，至少不应把该路径失败直接归咎游戏代码。

这只补证玩法与时间边界，不认证全部 WebGL 视觉表现或整个 manifest。方案步骤和游戏实现的其他主张仍需单独核验。
